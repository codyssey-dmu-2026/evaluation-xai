[문서 안내](README.md) · [상세 기준서](evaluation_specification.md) · [현재 구현 상태](implementation_status.md)

기준 원안: v1.0 / 저장소 정리일: 2026-09-28.

목적은 세 가지다. **투자 성과를 동일한 조건으로 비교하고, 차이의 통계적 의미를 확인하고, 모델의 비중 결정을 설명한다.**

> 과제 필수와 Evaluation 기본값을 구분한다. 아래 항목은 평가할 기준이지 달성 실적이 아니다.
> 현재는 합성 데이터 기반 초기 구현 단계이며, 실데이터·PPO·통합 서비스의 최종 검증은 남아 있다.

정규화·뉴스 수집·PPO 학습·전체 서비스 구축을 평가 담당 혼자 구현한다는 의미는 아니다. 각 담당자의 산출물을 받아 검증한다. 전체 과제에는 5개 API, 6개 화면 등 별도 요구가 있으며 이 표가 전체 요구사항을 대체하지 않는다.

### 12개 지표

- 수익률: 누적수익률, CAGR.
- 리스크: 연환산 변동성, VaR(95%), CVaR(95%), MDD.
- 위험조정: Sharpe, Sortino, Calmar.
- 상대성과: Alpha, Beta, Information Ratio.

ANOVA의 p<0.05 달성 자체는 필수가 아니다. 비유의하면 효과 크기와 원인을 분석한다. **표본 부족으로 검정을 실행하지 못한 것**과 **정상 검정 결과가 비유의한 것**은 다르다.

## 2. Evaluation에서 정한 기본값

| 항목 | 기본값 | 성격·주의점 |
| --- | --- | --- |
| 평가 구간 | WF2022~2025, 각 4년 학습·1년 테스트 | 과제 최소 2개보다 많은 내부 설정. 가격 준비 기간은 2017년부터 요청 |
| 반복 학습 | 보상 3종×4구간×seed 11/22/33 = 36회 | 실제 학습 완료 수가 아님. λ 탐색·통합 모델 재학습은 별도 |
| 대표 PPO | R3(수익률−MDD 페널티), 그림 seed=11 | 테스트 성적을 보고 대표 전략을 바꾸지 않음 |
| 자산·통화·기준지수 | 미국 ETF 10개·USD·S&P 500 연구안 | **팀 최종 확정 전. 혼합 12자산에 자동 적용 금지** |
| 기준 전략 | MVO 최소분산·월간, 동일가중 월간 | PPO 일간과 거래 빈도가 다르므로 회전율·비용도 보고 |
| 거래·계좌 | 이전 거래일 정보→다음 종가 모의 체결, 초기 100,000, 현금 이자 0 | 통화·달력 합의 필요. 실제 주문 체결이 아님 |
| MDD 이후 | 다음 체결 가능 종가에 청산→테스트 종료까지 현금 | 종료 뒤 기록을 삭제하거나 새 계좌를 이어 붙이지 않음 |
| 통계 표본 | 월별 비용 차감 후 단순수익률, PPO는 같은 월 seed 평균 | MVO/EW를 seed 수만큼 복사하지 않음 |
| 국면 | 월 시작 직전 60거래일 시장수익률: >+5% 상승, <−5% 하락, 나머지 횡보 | 사후 월 수익률로 분류 금지 |
| 유의수준 | 0.05, 신뢰구간 95% | 원 p값·Holm 조정값·시계열 보완 분석을 구분 |
| 설명 | 안전 규칙 전 정책 비중의 Grouped Permutation SHAP | 안전 규칙 변경은 별도 로그. SHAP을 인과 증명으로 해석하지 않음 |

고정 자산 목록, 보상 수식·λ 선택, 통계 표본 부족 처리, SHAP 예산과 검증 오차는 상세 기준서에 있다. 4개 구간을 선택해놓고 좋은 2개 구간만 골라 전체 결과라고 보고하지 않는다.

## 3. 성능 목표의 판정 방법

기본안의 모든 구간과 seed가 유효할 때, seed별 테스트 일별 수익률을 시간순으로 연결해 지표를 다시 계산한다. 연도별 Sharpe/CAGR를 단순 평균하지 않는다.

1. `median_seed(PPO_R3 통합 Sharpe) − EW_MONTHLY 통합 Sharpe ≥ 0.20`
2. `median_seed(PPO_R3 통합 누적수익률) − 기준지수 통합 누적수익률 ≥ 0.10`

집계 방식은 내부 결정이며 과제 원문이 중앙값을 지정한 것은 아니다. 각 연도·seed 원본과 실패도 함께 보고한다. 0.10은 상대 증가율이 아니라 **10%p 차이**다. 기준지수는 미국 연구안에서는 S&P 500이며, 혼합 자산의 기준지수는 먼저 합의해야 한다.

## 4. 결과 표시 원칙

| 상태 | 의미 | 처리 |
| --- | --- | --- |
| 기능 구현 | 계산·연동 코드와 테스트 존재 | 실제 성과 달성과 구분 |
| 목표 달성/미달 | 유효한 실제 결과로 정해진 임계값 비교 | 좋은 결과만 선별하지 않음 |
| incomplete | 필수 구간·seed·검정·설명이 미완료 | 최종 통과 판정 보류 |
| data_invalid | 미래 정보, 통화 혼합, 원장 불일치 등 | 해당 실행 중단·원인 기록 |
| 계산 불가 | 분모 0·표본 부족 등 | JSON null+이유. 0으로 대체 금지 |
| valid_with_warning | 계산 가능하지만 사전 정의한 경고 존재 | 경고와 영향 함께 공개 |

위는 보고 원칙이다. 현재 코드의 상태 문자열·HTTP 응답 매핑은 [구현 상태](implementation_status.md)를 확인한다.

## 5. 팀원에게 공유할 요청

- Data Pipeline: 정규화 전 수정주가, 같은 통화·날짜의 벤치마크/RF, 가격·뉴스 가용시각, fold별 scaler와 피처 순서.
- RL: 모델·seed·보상·스텝·학습 로그, 실제 action→weight 변환, 계좌 원장, 결정 ID, 보호규칙 전후 비중, 학습 구간 SHAP 배경 관측값.
- RAG: 출처와 시각이 있는 risk tag, 유효기간, 적용 규칙·결정 연결, 뉴스 확보 기간.
- 프론트/API: 합성/실제 표시, null 사유, 정책 설명과 규칙 설명 분리, 동일 run/decision ID 조회.

네 가지 보너스는 원문에서는 선택이지만 팀 구현 범위에는 포함한다. Evaluation은 이상탐지·Vision·공정성·MLOps의 기록과 연동 효과를 확인하며, 해당 기능 전체를 대신 개발하는 역할은 아니다.

교육용이며 실제 투자 조언에 사용할 수 없다. 백테스트 성과는 미래 수익을 보장하지 않는다.
