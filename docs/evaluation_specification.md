## 0. 이 문서의 사용 방법

- **과제 필수**: 원문에서 요구한 조건. 임의로 완화하지 않는다.
- **v1.0 결정**: 과제에서 정하지 않은 부분에 이번에 정한 프로젝트 기본값. 보편적인 금융·통계 표준이라는 뜻은 아니다.
- **연동 요청**: 다른 파트가 Evaluation에 전달해야 할 정보와 동작 규칙. 팀원에게 공유하고 구현 가능 여부를 확인한다.

저장소에서 확인할 목표 입력 필드는 9절에 정리했다. 이전 개인 메모인 Data Spec v0.1을 별도로 구하지 않아도 이 문서를 읽을 수 있다. 현재 코드가 받는 입력은 [팀 전달 자료](team_handoff.md), 목표와의 차이는 [구현 상태](implementation_status.md)를 확인한다. SHAP 출력은 개별 피처 단위에서 묶음 단위로 명시적으로 버전을 변경한다(9절). 현재 팀에서 이미 확정한 자산·거래 환경과 충돌하면 테스트 실행 전에 버전을 올려 변경한다. 결과가 마음에 들지 않는다는 이유로 테스트 기간·통계 기준을 바꾸지 않는다.

기본 순서: ① 기준 공유 → ② 작은 연동 샘플 검사 → ③ 설정·데이터 버전 동결 → ④ 최종 평가 → ⑤ 결과와 한계 보고.

## 2. 데이터·기간 기준

### 2.1 Walk-Forward 구간

아래 4개 구간은 Evaluation 기본안이다. 과제 필수는 최소 2개 구간이며, 4개 모두의 데이터 확보·학습 완료는 별도로 검증한다. 1년씩 이동하는 두 구간을 구성하려면 준비 기간을 제외해도 보통 최소 6년의 연속 가격 범위가 필요하다.

| fold_id | 최종 모델 학습 기간 | 테스트 기간 |
|---|---|---|
| WF2022 | 2018-01-01~2021-12-31 | 2022-01-01~2022-12-31 |
| WF2023 | 2019-01-01~2022-12-31 | 2023-01-01~2023-12-31 |
| WF2024 | 2020-01-01~2023-12-31 | 2024-01-01~2024-12-31 |
| WF2025 | 2021-01-01~2024-12-31 | 2025-01-01~2025-12-31 |

- 날짜는 달력상의 경계이고 실제 행은 미국 시장 거래일만 사용한다.
- 과제에 따라 10개 이상 자산의 5년 이상 **수정가격을 yfinance 또는 pykrx로 자동 수집**해야 한다. 이 평가안의 미국 ETF 기본값에서는 yfinance를 사용하며, 실제 공통 기간 확보 여부를 수집 결과로 검사한다.
- 매 구간 PPO와 정규화기를 새로 만든다. 이전 모델을 이어 학습하지 않는다.
- 준비 기간 자료는 RSI·MACD·MVO 공분산 계산에만 사용한다. 최종 PPO의 학습 구간을 몰래 늘리지 않는다.
- 테스트 첫날에 과거 학습 기간의 마지막 N일 피처를 참조하는 것은 허용한다. 미래 테스트 수익률로 정규화하거나 설정을 고르는 것은 금지한다.
- 초기 연동 시험은 WF2022 하나로 진행하되 `development`로 표시한다. 그 결과를 보고 설계를 바꿨다면 2022년을 완전히 미관측인 최종 테스트였다고 주장하지 않는다. 이미 확인한 기간은 보고서에 공개한다.

### 2.2 입력 피처와 전처리

연동 시작값은 N=20거래일, 수정종가 로그수익률, RSI(14), MACD(12,26,9), 현재 보유 비중이다. 1·5·20일 수익률이나 20일 변동성은 추가할 수 있지만 실제 피처 목록은 `feature_schema.json`에 명시한다. Evaluation 코드는 입력 차원을 고정하지 않는다.

- 자산·피처의 이름, 순서, lag, 원래 단위, 모델 입력 shape와 dtype을 기록한다.
- 연속 시장 피처는 학습 구간에서 적합한 Z-score를 기본으로 한다. 비중·상태 플래그 등은 별도 변환 여부를 기록한다.
- 정규화는 한 곳에서만 한다. 전처리기가 이미 변환한 값을 `VecNormalize`가 다시 변환하지 않도록 한다.
- 평가 시 통계 업데이트와 보상 정규화를 끈다. 지표는 정규화 보상이 아닌 실제 계좌 수익률로 계산한다. [SB3 정규화 문서](https://stable-baselines3.readthedocs.io/en/master/guide/vec_envs.html#vecnormalize)
- 가격은 배당·분할 조정을 포함한 수정종가로 계산한다. 이를 사용한 뒤 배당을 다시 현금으로 더하지 않는다.
- 지금 내려받은 수정가격이 과거 당시의 데이터 공급본과 완전히 같다는 보장은 없다. 수집본과 조정 방식을 고정하고, 소급 수정·고정 자산 선정에 따른 연구 한계도 기록한다.
- 가격 결측은 상장 이후의 단일 거래일 공백에만 1일 한도 Forward Fill을 허용하고 표시한다. 남은 결측은 전처리에서 제외하되, 최종 테스트의 필수 거래일이 빠지거나 보간된 체결가격이 있으면 해당 평가는 `data_invalid`로 중단한다. 수익률·거래량은 전방 채움하지 않는다.
- 원시 OHLCV와 수정종가를 구분해 저장하고 수집 옵션을 명시한다. v1.0의 yfinance 수집 제안은 `auto_adjust=False`로 원시 가격과 수정종가를 구분하는 방식이다. 이 옵션값 자체는 과제 필수가 아니다. `auto_adjust=True` 수집본을 받으면 수정 여부와 원시 OHLCV의 별도 확보 여부를 명시하고 이중 조정하지 않는다. 어느 방식이든 기본값에 의존하지 않고 수집 옵션과 종료일의 포함 여부를 기록한다. [yfinance 문서](https://ranaroussi.github.io/yfinance/reference/api/yfinance.download.html)

### 2.3 벤치마크와 무위험수익률

- **과제 목표 판정 기준**: S&P 500 가격지수(`SP500_PRICE`, 수집 티커 `^GSPC`). Alpha·Beta·Information Ratio의 주 기준도 동일하다.
- **보조 비교**: SPY 수정가격 기반 매수 후 보유 전략. 배당 반영 자산과 가격지수 사이 차이를 함께 보여 준다. 이를 S&P 500 공식 총수익지수와 동일하다고 부르지 않는다.
- **무위험수익률**: Kenneth French의 미국 일별 Fama/French 3 Factors 파일 중 `RF`. 퍼센트 값을 100으로 나눠 일별 소수 수익률로 사용한다. 월별 RF나 연율 금리를 일별 수익률에서 그대로 빼지 않는다.
- RF는 성과 평가용이며 PPO 입력이나 실제 현금 수익으로 자동 사용하지 않는다. 이 자료의 RF 원천은 2024년 6월을 경계로 변경되었으므로 다운로드 버전을 보존한다. [Kenneth French 자료 설명](https://mba.tuck.dartmouth.edu/pages/faculty/ken.french/Data_Library/f-f_factors.html)
- 벤치마크·RF 날짜 누락은 오류로 표시한다. 0으로 채우거나 해당 날짜를 조용히 삭제하지 않는다.

## 3. 공통 거래·Safe-Guard 기준

### 3.1 하루의 처리 순서

1. 이전 거래일 장 마감 후 30분을 정보 마감 시각으로 둔다. 조기 폐장·서머타임은 거래소 달력을 따른다.
2. 그때까지 이용 가능했던 정보로 다음 거래일 주문을 결정한다. 이후 발표된 뉴스는 다음 의사결정으로 넘긴다.
3. 다음 거래일 종가까지는 기존 보유분으로 수익·손실을 계산한다.
4. 해당 종가 기준으로 예약된 비중 변경을 모의 체결하고 비용을 차감한다.
5. 계좌 가치·실제 비중·drawdown을 기록하고 이후 의사결정에 사용한다.

`decision_at < execution_at`, `available_at <= decision_at`를 검사한다. `execution_at`은 실제 다음 거래일 종가 시각이다.

이 방식은 **수정가격 기반 총수익 모의 원장**이다. 수정종가를 실제 거래소 호가라고 주장하지 않는다. 소수점 수량 거래를 허용하며, 주문장·세금·시장충격의 정밀 모형은 포함하지 않는다. 장 마감 후 30분은 역사 자료 재생의 명시적 지연 가정이지 실제 데이터 공급 속도를 확인한 값이 아니다.

### 3.2 자금·비중·비용

- 각 테스트 직전 거래일 종가 시점의 초기 상태는 현금 100,000 USD다. 첫 주문은 그날의 정보로 정하고 테스트 첫 거래일 종가에 실행한다. 첫날 장중 수익은 얻지 않으며 진입 비용을 반영한다.
- 공매도·차입·레버리지를 사용하지 않는다.
- PPO·MVO의 일반 목표 비중은 10개 ETF 합계 1, 각 ETF 0~0.40으로 맞춘다. MVO 40% 상한은 과제 필수, PPO에도 적용하는 것은 v1.0의 공통 비교 조건이다.
- 40%는 **리밸런싱 목표 비중 상한**이다. 거래 사이 가격 변동으로 실제 비중이 이를 넘는 경우는 따로 기록하며 자동 거래를 추가하지 않는다.
- 현금은 ETF 10개와 별도의 원장 항목이다. BIL과 현금을 같은 것으로 처리하지 않는다. 안전 규칙으로 줄인 투자금은 현금에 둘 수 있으며, 현금 수익률은 0으로 고정한다.
- 모든 실제 비중은 현금을 포함해 합계 1이어야 한다. 허용 오차는 1e-6.
- 거래대금 = ETF별 실제 매수대금 + 실제 매도대금의 합. 수수료 = 거래대금×0.00015, 슬리피지 비용 = 거래대금×0.0005.
- 예: A를 10,000달러 팔고 B를 10,000달러 사면 거래대금은 20,000달러, 총 비용은 13달러다. 매도·매수 합계에 다시 왕복 배수를 곱하지 않는다.
- 비용은 공통 거래 원장이 한 번만 반영한다. 현금이 음수가 되지 않도록 비용을 포함해 주문 수량을 정한다. 비용이 포함된 체결가격을 쓰는 구현으로 바꾸면 별도 슬리피지 차감을 제거해야 한다.
- 테스트 마지막 날에는 미리 정한 종료 청산을 실행하고 비용을 포함한다. 마지막 날 일반 리밸런싱과 청산을 중복 실행하지 않는다.
- 시장지수는 거래 가능한 계좌가 아니므로 거래비용 없는 참조 수익률이다. SPY 보유 전략은 다른 전략과 같은 진입·청산·비용 모형으로 별도 실행한다.

### 3.3 MDD 15% 초과

- drawdown = 1 − 현재 계좌 가치 / 해당 구간의 과거 최고 계좌 가치. 초기 자금도 최고점 계산에 포함한다.
- 조건은 엄격하게 `drawdown > 0.15`이다. 정확히 0.15일 때와 넘었을 때를 따로 테스트한다.
- **학습**: 과제대로 에피소드를 종료한다.
- **평가**: 학습 환경의 종료 신호를 기록하고, 계좌 기록은 멈추지 않는다. 이후 첫 체결 가능 종가에 전량 청산하고 구간 종료까지 현금으로 유지한다. 청산 전 가격 변동과 청산 비용도 포함한다.
- 남은 기간에 계좌를 초기화해 재진입하지 않는다. 다음 독립 Walk-Forward 구간에서만 초기화한다.
- 기본 비교의 PPO·MVO·동일가중 모두 같은 계좌 MDD 규칙을 적용하고 전략명에 `guarded`를 표시한다. MVO·동일가중의 MDD 규칙 없는 결과도 보조표에 제시해 안전 규칙 자체의 영향을 구분한다.
- 청산이 지연되므로 실제 MDD가 15%를 넘을 수 있다. 이 규칙을 ‘최대 손실 15% 보장’으로 설명하지 않는다.
- SB3 평가에서 `done` 이후 자동 reset된 계좌를 이어 붙이지 않는다. 별도 평가 원장이 종료 후 현금 구간을 기록한다.

## 4. 비교 전략·학습 반복 기준

### 4.1 전략 목록

| 전략 ID | 내용 | 일반 리밸런싱 |
|---|---|---|
| PPO_R1 | 비용 차감 후 수익률 보상 | 매 거래일 |
| PPO_R2 | 수익률 / 변동성 보상 | 매 거래일 |
| PPO_R3 | 수익률 − λ×MDD 보상. 대표 PPO | 매 거래일 |
| MVO_MINVAR | 과거 252거래일 공분산으로 최소 분산 계산 | 매월 첫 거래일 종가 |
| EW_MONTHLY | 10개 자산에 각각 10% | 매월 첫 거래일 종가 |
| SPY_HOLD | SPY 매수 후 보유, 계좌 MDD 종료 없음 | 최초 진입·최종 청산만 |
| SP500_PRICE | S&P 500 가격지수 | 거래 전략이 아닌 참조 지수 |

MVO·동일가중은 첫 테스트 거래일에도 진입한다. 월간 주문은 이전 거래일 정보로 정한다. 계좌 MDD 청산은 월간 일정과 무관한 비상 동작이다.

PPO와 월간 기준 전략은 거래 빈도가 다르다. 따라서 주 결과는 ‘이 운영 규칙을 포함한 전략의 비교’이며 PPO 알고리즘만의 순수한 효과가 아니다. 회전율·총 비용·거래 횟수를 보조 지표로 항상 제공하고, 저비용 보완 비교로 `EW_DAILY`도 실행한다. 12개 필수 지표를 이 보조 지표로 대체하지 않는다.

### 4.2 MVO 구현 기본값

- 목적함수: 최소 분산 `wᵀΣw`. 기대수익 추정에 추가로 의존하지 않는 기준 전략을 만들기 위한 선택이다.
- 공분산: 의사결정 시각까지의 수정가격 **일별 단순수익률 252개**, 표본 공분산. 원본 로그수익률에서 `expm1`으로 변환할 수 있다.
- 제약: 비중 합계 1, 각 비중 0~0.40. 현금은 MVO의 일반 최적화 대상이 아니다.
- 구현: `scipy.optimize.minimize(method='SLSQP')`, 초기값 동일가중, `maxiter=1000`, `ftol=1e-9`.
- `success`뿐 아니라 실제 비중·합계 제약도 검사한다. 미수렴 시 그 주문의 목표를 동일가중으로 대체하고 실패 사유를 남긴다.
- 대체 횟수가 한 번이라도 있으면 `valid_with_warning`, 월간 최적화 시도의 10%를 초과하면 정식 MVO 성과 판정을 보류한다. 10%는 프로젝트 운영 기준이지 통계 법칙이 아니다.
- 공분산 데이터가 부족한 오류는 최적화 실패로 숨기지 않고 입력 오류로 처리한다. [SciPy SLSQP 문서](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-slsqp.html)

### 4.3 보상 함수와 반복 학습

- 최종 비교는 3개 보상×4개 구간×3개 seed = **36회 PPO 학습**이다. 각 모델은 최소 100,000 환경 스텝을 학습한다. 실제 SB3 학습 스텝이 rollout 단위로 조금 늘어나면 실제 값을 기록하고 조건별 예산을 맞춘다.
- 같은 구간·seed에서는 네트워크, 관측값, 학습 예산, 비용·거래 규칙을 같게 두고 보상 함수만 바꾼다. 모델 구조 자체는 RL 담당 구현을 사용하되 설정을 버전으로 고정한다.
- 공통 `r_t`는 비용 차감 후 포트폴리오 **일별 로그수익률**이다. R2의 σ는 직전까지의 해당 에피소드 일별 로그수익률과 현재 값을 합친 최근 20일 표본 표준편차, 최소 분모 1e-4로 정한다. 표본이 2개 미만이면 분모 1e-4를 쓴다. 이는 정식 연환산 Sharpe 자체가 아니라 과제의 Sharpe형 보상이다.
- R3의 MDD는 해당 시점까지의 최대 drawdown 크기(양수)다. 부호를 음수로 넣어 손실에 보상을 주는 오류를 검사한다.
- λ=1.0을 첫 실험의 기본값으로 시작한다. 이후 후보 0.5, 1.0, 2.0, 5.0을 2018~2020년 내부 학습 / 2021년 내부 검증에서 3개 seed로 비교한다. 검증 Sharpe의 seed 중앙값이 가장 높은 λ를 선택한다. 1e-6 이내 동률이면 MDD 중앙값이 작은 값 → 1에 가까운 값 → 작은 λ 순서로 정한다.
- λ 탐색은 별도 12회 학습이며 이때도 동일 예산을 적용한다. 세 seed의 평가가 모두 유효하고 Sharpe가 유한한 후보만 선택 대상이다. 모두 유효한 선택 점수가 없으면 λ=1.0을 기본값으로 쓰고 선택 실패를 보고한다. 이후 모든 최종 구간에서 선택한 λ를 고정하고, 각 구간의 전체 4년으로 새로 학습한다.
- 수익률−MDD 트레이드오프 곡선은 이 **내부 검증** 결과로 만든다. 테스트 결과로 λ를 다시 고르지 않는다.
- RL 담당에게 모델·seed·보상 종류별 Episode Reward 학습 로그를 요청하고 수렴 여부와 함께 시각화한다. 서로 단위가 다른 세 보상의 곡선을 ‘성과가 더 높다’는 비교 근거로만 사용하지 않는다.
- 관측 구조에 리스크 태그를 추가해 재학습하는 확장 실험은 위 36회에 포함하지 않는다. 필요한 추가 학습량을 별도 기록한다.

## 5. 12개 성과지표 계산·판정

입력: 거래 원장의 비용 차감 후 계좌 가치와 수익률. `r`=일별 순 단순수익률, `f`=일별 RF, `b`=벤치마크 단순수익률, `e=r−f`, 연환산 A=252. 표준편차는 ddof=1.

| 지표 | v1.0 계산 기준 |
|---|---|
| 누적 수익률 | `V_end / V_start − 1` |
| CAGR | `(V_end / V_start)^(1 / years) − 1`, years=원장 시작~종료 실제 일수/365.25 |
| 연환산 변동성 | `std(r) × sqrt(252)` |
| VaR 95% | 일별 손실 `−r`의 95% 분위수, 선형 보간 |
| CVaR 95% | 손실이 VaR 이상인 관측값의 평균, 경계 동률 포함 |
| MDD | 초기 자금을 포함한 `max(1 − V / 누적 최고 V)` |
| Sharpe | `mean(e) / std(e) × sqrt(252)` |
| Sortino | `mean(e) / sqrt(mean(min(e,0)^2)) × sqrt(252)` |
| Calmar | `CAGR / MDD` |
| Alpha | `r−f = α_daily + β(b−f) + ε` OLS 회귀, 연환산 α=`252×α_daily` |
| Beta | 위 회귀의 β |
| Information Ratio | `mean(r−b) / std(r−b) × sqrt(252)` |

- VaR·CVaR는 ‘일간 / 역사적 방법 / 95%’라고 표시하며 연환산하지 않는다. 손실 분위수가 음수라면 이를 자동 절댓값·0으로 바꾸지 않는다.
- 모델 입력과 로그 원장은 로그수익률을 유지하되, 위 복리·위험 지표에는 단순수익률을 사용한다. `r = exp(log_return)−1`로 변환하고 변환 여부를 메타데이터에 남긴다.
- 포트폴리오 로그수익률을 ‘종목별 로그수익률의 비중 가중합’으로 대체하지 않는다.
- 분모 0, 표본 부족, 계좌 가치가 양수가 아니어서 CAGR 등이 정의되지 않는 경우는 `null + reason`. 0으로 위장하지 않는다.
- 구간별 원본 결과와 각 지표의 seed 중앙값·최솟값·최댓값을 모두 보관한다. 평균 비중·평균 수익률로 가상의 ‘최고 대표 계좌’를 만들지 않는다.
- 예정한 세 seed 중 실패·누락이 있으면 남은 seed만으로 최종 통과 판정을 하지 않는다. 부분 기술통계는 표본 수와 함께 제공하고 `incomplete`를 표시한다.
- 전체 결과는 seed별로 4개 비중복 테스트 수익률을 이어 붙여 다시 계산한다. 구간 Sharpe나 CAGR을 산술평균하지 않는다. 구간 시작·종료 비용도 유지한다.
- 이 통합 곡선은 **매년 청산·재학습·위험 상태 재설정**을 가정한 평가 곡선이다. 한 계좌의 MDD 상태가 4년 내내 유지되는 운용과는 다르다. 구간별 MDD와 전체 연결 곡선 MDD를 모두 보여 준다.

### 과제 수치 목표의 판정

대표 PPO_R3에 대해 아래를 개별 판정한다.

1. `median_seed(통합 Sharpe_PPO) − 통합 Sharpe_EW_MONTHLY >= 0.20`
2. `median_seed(통합 누적수익률_PPO) − 통합 누적수익률_SP500_PRICE >= 0.10`

0.10은 상대적으로 10% 증가가 아니라 **10%p 차이**다. 개별 seed·개별 연도의 달성 여부와 SPY 보유 대비 차이도 숨기지 않는다. 이 통합·중앙값 판정은 과제의 수치에 v1.0이 정한 집계 방식이다. 하나라도 필수 구간이 없으면 전체 최종 판정은 `incomplete`이다.

기능 구현 완료와 수익률 목표 달성은 별도 상태다. 목표를 못 맞췄다고 테스트 기간을 바꾸거나 결과를 누락하지 않는다.

## 6. ANOVA·Tukey HSD 기준

### 6.1 무엇을 표본 하나로 보는가

- 한 표본은 **한 전략의 한 달 비용 차감 후 수익률**이다.
- 월별 수익률 = 해당 월 일별 순수익률을 복리로 연결한 `prod(1+r_t)−1`.
- PPO는 먼저 seed별 월 수익률을 만든 뒤 같은 달의 3개 seed 산술평균을 사용한다. 이 값은 ‘학습 반복의 평균 결과’이며 실제 한 계좌·앙상블 운용 수익률이라고 부르지 않는다.
- MVO·동일가중은 각 달에 한 값만 사용한다. PPO seed 수에 맞춰 같은 값을 복사하지 않는다.
- 4개 연도가 정상 확보되면 전략당 48개 월 관측값이다. seed 원본은 별도 보존한다.
- 보상 함수의 Episode Reward 숫자 자체를 서로 비교하지 않는다. 보상식마다 척도가 다르므로 공통 월 수익률로 비교한다.
- 주 검정은 월 수익률 하나로 사전 고정한다. 12개 지표를 모두 검정해서 작은 p값만 선택하지 않는다. Sharpe·MDD 등은 성과표 및 별도 민감도 분석으로 제공한다.

### 6.2 시장 국면 정의

매월 첫 거래일의 **직전 거래일** S&P 500 종가와 그보다 60거래일 전 종가로 수익률을 계산한다.

- +5% 초과: 상승장.
- −5% 미만: 하락장.
- 나머지: 횡보장. 정확히 ±5%는 횡보장.

월 시작 시점에 분류를 고정해 그달 전체에 적용한다. 해당 월이 끝난 뒤 얻은 수익률로 그달 국면을 정하지 않는다. 60일·±5%는 비교를 위한 프로젝트 분류 규칙이며 시장 국면의 유일한 정답은 아니다.

### 6.3 필수 검정과 기록

아래는 목표 통계 명세다. 현재 코드에서 일부 검정이 불가능하면 Holm 전체를 `incomplete`로 두며, 아래의 결측 자리 처리 방식은 아직 구현하지 않았다. [구현 차이](implementation_status.md)를 함께 확인한다.

| ID | 분석 | 비교 대상 |
|---|---|---|
| A1 | One-way ANOVA | PPO_R1 / PPO_R2 / PPO_R3 |
| A2 | One-way ANOVA | PPO_R3 / MVO_MINVAR / EW_MONTHLY |
| A3 | Two-way ANOVA | 위 세 전략 × 상승·횡보·하락 국면 |

- 구현: `statsmodels`의 OLS와 `anova_lm`. A1·A2는 한 요인 모형, A3는 `monthly_return ~ C(strategy, Sum) * C(regime, Sum)`와 Type III 제곱합을 사용한다.
- A3는 전략, 국면, 상호작용을 각각 보고한다. 상호작용은 ‘어떤 전략이 나은지가 시장 국면에 따라 달라지는가’를 뜻한다.
- 기록: 분석식·표본 수·자유도·F·원 p값·효과 크기·가정 점검·해석 상태.
- η²는 각 효과의 SS / 전체 중심화 SS로 계산해 사용한 SS 유형을 함께 표시한다. A3의 효과별 값은 서로 겹칠 수 있어 합계 1인 기여율로 해석하지 않는다. partial η²=`SS_effect/(SS_effect+SS_error)`를 추가하면 반드시 다른 이름으로 표시한다.
- 5개 핵심 p값(A1, A2, A3의 세 효과)에 Holm 조정값도 함께 기록한다. 과제의 Tukey 실행 조건은 원 p값 `<0.05`로 유지한다. [statsmodels ANOVA 문서](https://www.statsmodels.org/stable/generated/statsmodels.stats.anova.anova_lm.html)
- 검정 불가 항목의 p값은 공개 결과에서 null로 둔다. Holm의 사전 지정 가족 크기 5를 유지하려면 내부 조정 계산에만 해당 자리를 1로 채우며, 이를 실제 검정 p=1이라는 결과로 보고하지 않는다.

### 6.4 Tukey HSD

- A1·A2의 원 p<0.05이면 해당 세 집단의 모든 쌍을 Tukey HSD로 비교한다.
- A3의 효과 중 원 p<0.05가 있으면 ‘전략×국면’의 최대 9개 셀을 하나의 비교군으로 두고 Tukey를 계산한다. 하나의 36쌍 비교 가족 안에서 조정하며, 보고서에서는 같은 국면의 전략 비교와 같은 전략의 국면 비교를 중심으로 해석한다.
- 표본 부족·빈 셀로 A3 자체가 불가능하면 사후검정도 실행하지 않고 이유를 기록한다.
- `group_a`, `group_b`, `mean_b−mean_a`, 조정 p값, 95% 신뢰구간, 기각 여부, 비교 가족을 저장한다.
- A3의 상호작용이 중요하면 모든 국면을 섞은 전략 평균만으로 결론 내리지 않는다. [statsmodels Tukey 문서](https://www.statsmodels.org/stable/generated/statsmodels.stats.multicomp.pairwise_tukeyhsd.html)

### 6.5 금융 시계열의 의존성 처리 — 반드시 포함

같은 달의 전략들은 같은 시장 충격을 받는다. 월별로 묶어도 독립 표본이 되는 것은 아니다. 따라서 **기본 ANOVA·Tukey는 과제 필수 형식의 탐색적 결과**로 표시하고, p<0.05만으로 전략의 우수성이 증명됐다고 쓰지 않는다. 독립성·정규성·등분산은 고전적 ANOVA의 전제다. [SciPy ANOVA 문서](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.f_oneway.html)

보완 분석을 v1.0의 고정 작업으로 둔다.

- 주 비교: PPO_R3 − EW_MONTHLY의 **평균 월 수익률 차이**.
- 방식: 동일 월의 모든 전략 값을 한 행으로 묶고, 연속된 월 묶음을 함께 다시 뽑는 ‘짝지은 블록 부트스트랩’.
- 구현: `arch.bootstrap.CircularBlockBootstrap`, 각 연도 안에서 블록 길이 3개월로 12개월을 재표집하고 4개 연도를 합친다. 같은 추출 인덱스를 모든 전략 열에 적용한다.
- 반복 5,000회, 난수 seed=20260926. percentile 방식의 95% 신뢰구간을 보고한다. 다른 전략 쌍은 보조·탐색 결과로 별도 표시한다.
- 블록 길이 1개월·6개월도 미리 정한 민감도 분석으로 함께 실행한다. 3개월 결과와 0 포함 여부가 바뀌면 `unstable_interval` 경고를 붙인다. 유리한 길이만 남기지 않는다.
- 신뢰구간이 0보다 높으면 ‘해당 기간·재표집 가정에서 평균 월 수익률 차이가 양수인 근거’라고 표현한다. Sharpe 목표 달성이나 미래 수익 보장으로 확대하지 않는다.
- 이는 관측한 기간에 조건부인 근사 분석이다. 4개의 테스트 연도만으로 모든 미래 시장을 대표하거나 의존성·비정상성을 완전히 해결하지는 않는다. [arch 시계열 부트스트랩 문서](https://bashtage.github.io/arch/bootstrap/timeseries-bootstraps.html)

가정·표본 점검:

- 잔차 Q-Q plot, Shapiro–Wilk, Levene(중앙값 기준), 월별 잔차의 자기상관 및 Ljung–Box(lag 3)를 저장한다. 진단 p값이 크다고 독립성이 증명되지는 않는다.
- A1·A2는 집단별 12개월 미만이면 `insufficient_sample`. A3는 셀별 최소 6개월과 설계행렬 full rank를 요구한다. 미달 시 기술통계와 부족 사유를 제공하고 **노션의 3가지 ANOVA 완료 요구를 충족하지 못한 상태**로 기록한다.
- 12개월·6개월은 계산·보고를 위한 최소 운영 기준이며 충분한 검정력 보장이 아니다. 국면이 부족하다고 경계를 사후에 바꾸지 않는다.
- p≥0.05는 ‘차이를 입증할 근거 부족’이지 ‘동일한 전략’이라는 뜻이 아니다.

## 7. SHAP 기준

### 7.1 무엇을 설명하는가

설명 함수는 다음 전체를 포함한다.

`실제 관측값 → 학습 때와 같은 전처리 → deterministic PPO → 행동의 비중 변환·40% 제약 → weight_policy`

- `weight_policy`: 모델과 정해진 행동 변환이 제안한 비중.
- `weight_executed`: 뉴스·이상탐지·계좌 안전 규칙과 실제 체결을 거친 비중.
- SHAP은 첫 번째를 설명한다. 두 번째가 달라진 이유는 `risk_actions`의 규칙·태그·변경 전후 비중으로 설명한다.
- 태그가 PPO 입력에 없고 Safe-Guard에만 쓰였으면 그 태그의 PPO SHAP 기여도를 만들지 않는다.
- SHAP의 기준값은 설명용 배경 데이터에 대한 모델 평균 출력이지 어제 비중이나 동일가중 비중이 아니다. +0.03은 비중 +3%p 기여이지 수익률 +3%라는 뜻이 아니다.

### 7.2 구현·계산량 기본값

아래 seed와 예산은 최종 실험에 명시적으로 전달할 설정이다. 현재 설명 함수의 기본 seed는 11이므로, 설정을 생략한 데모를 이 명세의 최종 설명으로 취급하지 않는다.

- `shap.PermutationExplainer`를 사용한다. 기존 메모의 KernelExplainer는 시작 후보였으며 v1.0에서는 반복 계산량과 전체 비중 출력의 연결을 명시하기 위해 Permutation 방식으로 정한다. 이 설명기는 사용자 예측 함수와 사용자 masker를 받을 수 있다. [SHAP 공식 문서](https://shap.readthedocs.io/en/latest/generated/shap.PermutationExplainer.html)
- 고정 피처 묶음에 대한 **Grouped SHAP**을 계산한다. 자산별 과거 N일 수익률은 한 묶음, 자산별 RSI는 한 묶음, MACD 관련 값은 한 묶음, 현재 포트폴리오 비중 전체는 한 묶음, 자산별 리스크 벡터는 한 묶음으로 둔다. 기타 입력도 누락 없이 묶음에 매핑한다.
- 이유: 수백 개의 시차 입력을 그대로 표시하는 부담을 줄이고, 현재 비중 중 일부만 바꿔 합계가 깨지는 일을 막는다. `masker`는 숨길 묶음 전체를 같은 배경 행의 값으로 대체한다. 묶음 기여도를 개별 날짜·개별 피처의 SHAP 값인 것처럼 표시하지 않는다. 단순히 숫자 열 이름만 묶는 것이 아니라, 실제 마스킹 단위가 묶음이 되도록 별도 어댑터를 구현·시험한다.
- 배경 데이터는 **같은 모델로 그 모델의 학습 기간을 재실행한 실제 관측값**에서 32개를 시기별로 고르게 선택한다. 정규화기는 고정한다. 동적 현재 비중을 임의 동일가중 값으로 채우지 않는다.
- 설명 대상은 대표 PPO_R3, seed=11, 각 테스트 월 첫 거래일 주문의 관측값 12개/구간이다. 청산 후 주문이 없는 달은 제외하고 제외 수를 기록한다.
- 추가 사례: 최초 MDD 종료 결정, 최초 유효 리스크 태그로 비중이 바뀐 결정. 존재하지 않는 사례는 만들지 않는다. 사후 선택한 사례라는 표시를 한다.
- 자산별 비중 10개를 같은 예측 함수의 출력으로 받아 저장한다. 기본 반복 수는 10, 피처 묶음 수 G에 대해 `max_evals=10×(2G+1)`, 배경/배열 처리 batch_size=32, 설명 seed=20260926으로 둔다.
- 모델을 한 번에 하나씩 CPU에서 처리한다. 이 개수는 초기 예산이며 M3 16GB에서의 소요 시간을 측정한 값은 아니다.
- 묶음 대체도 수익률·지표 간 모든 상관관계를 보존하지는 않는다. 학습 분포 밖 조합이 생길 수 있고, SHAP은 인과관계나 투자 정답을 증명하지 않는다는 한계를 보고한다.

### 7.3 합격·경고 기준

1. 실제 예측 함수와 설명 함수의 비중 차이: 자산별 절댓값 ≤1e-6.
2. `base_value + sum(SHAP) − weight_policy` 절댓값 ≤1e-3. 실패하면 정상 설명으로 공개하지 않는다.
3. 1번·2번 통과는 설명 안정성을 보장하지 않는다. 각 구간의 첫 유효 정기 설명을 난수 seed 20260927로 한 번 더 계산해 기여도 차이를 저장한다. 최대 묶음 기여도 차이 >0.01이면 `unstable_explanation` 경고를 붙인다. 결과가 안정적인 것만 골라 숨기지 않는다.
4. 구간별·자산별 묶음 SHAP Summary Plot과 대표 Force Plot을 각각 최소 1개 만든다. 첫 공개 예시는 SPY·seed 11의 첫 유효 결정으로 고정한다. 실제 자료가 없으면 `not_available`이다. Summary는 SHAP 기여도의 절댓값 평균을 표시하는 bar 형식을 기본으로 한다.
5. API 결과에 모델 ID, 결정 ID, 타깃 자산, 설명 단계, 배경 ID, 묶음 정의, 계산 예산과 상태를 포함한다.

## 8. RAG·보너스 기능과 평가 연결

### 8.1 실험 종류 분리

- `core`: 가격·기술지표 + 공통 계좌 MDD 규칙. 지표·통계·SHAP 개발용 기준 실험.
- `integrated`: 과거 시점에 이용 가능했던 뉴스·공시 태그를 **PPO 관측 공간에 넣고**, 동일 태그를 Safe-Guard 모니터링에도 전달하는 실험. 노션의 미션 소개에 적힌 결합 흐름을 최종 통합 데모 기준으로 삼는다.
- `core` 성과를 `integrated` 성과라고 표시하지 않는다. 최종 제출에서 통합 실험의 데이터 기간·모델·규칙·실패 사례를 따로 제시한다.
- 기능 요구사항에는 태그를 관측 공간 **또는** 리스크 모니터링 모듈에 반영하는 연동 인터페이스가 적혀 있다. 한쪽만 연결한 단계도 기능 검증에는 기록할 수 있지만, 최종 통합 데모에는 미션 소개에서 제시한 관측 공간·Safe-Guard 연결과 뉴스→비중 변경 추적을 모두 보여 준다. 태그가 관측 공간에 들어간 모델은 해당 구조로 다시 학습한다.

뉴스 공통 확보 기간은 가격 기간과 별도로 검사한다. 예를 들어 FNSPID 원래 공개 자료는 1999~2023년 범위로 소개되어 있어, 그 파일만으로 2024~2025년 뉴스 평가까지 했다고 볼 수 없다. 해당 연도는 다른 당시 자료를 확보하거나 `coverage_missing`으로 표시한다. [FNSPID 작성자 저장소](https://github.com/Zdong104/FNSPID_Financial_News_Dataset)

기본 실험 기간은 유지한다. 통합 실험에서 일부 구간만 실행할 수 있으면 그 범위의 부분 결과만 보고하고 전체 통합 성능 판정은 보류한다. 부족한 뉴스를 ‘리스크 없음’으로 바꾸지 않는다.

### 8.2 위험 태그 전달 규격과 검증

필수: `tag_id`, `asset_id`, `risk_type`, `severity`, `confidence`, `published_at`, `available_at`, `generated_at`, `expires_at`, `source_url`, `tagger_version`.

- severity·confidence는 0~1. 금융 위험의 객관적인 확률로 자동 해석하지 않는다.
- live 실험은 실제 생성·수신 시각 이후만 이용한다. historical replay는 당시 원문과 미리 정한 가상 처리 지연으로 `simulated_available_at`을 만들고 실제 생성 시각은 별도 보관한다. 두 시각을 섞지 않는다.
- 게시일만 있고 시각이 없는 문서는 해당 원문 날짜가 끝난 후 다음 거래일 장 마감+30분부터 이용 가능하다고 보수적으로 가정하고 표시한다.
- 뉴스가 정책 입력에 들어가면 같은 피처 체계를 학습 때부터 사용한다. 테스트에만 새로운 태그 열을 붙이지 않는다.
- 위험 임계값·유효기간·종목 비중 축소 방식은 RAG/RL의 `risk_rule_config`로 전달받는다. Evaluation은 그 규칙을 테스트 전에 고정하고 실행 기록과 대조한다. 이 문서가 다른 파트의 위험 판단 알고리즘까지 대체하지는 않는다.
- 통합 데모의 한 사례에는 같은 `tag_id`에 대해 관측값 반영, 모니터링 상태, PPO 제안 비중, Safe-Guard 적용 비중, 원문 URL이 모두 연결돼 있어야 한다. 어느 경로가 실제 비중 변화를 만들었는지도 기록한다.
- 태그→규칙→결정→최종 비중의 연결 성공률은 유효 적용 대상 100%를 목표로 한다. 만료 태그 적용·미래 문서 참조·누락 ID는 연동 실패다.
- 위험 연동 효과는 같은 기간의 on/off로 비교한다. Guard만 바꾸면 같은 정책으로 재실행하고, 모델 입력이 달라지면 각각 재학습한다. 보조 분석으로 구분하고 유리한 사례만 선택하지 않는다.
- 과거 문서를 나중의 LLM으로 분석할 때 사전학습 지식이 개입할 가능성은 남는다. 날짜 필터만으로 이 한계가 완전히 사라졌다고 주장하지 않는다.

### 8.3 네 가지 보너스 기능에서 Evaluation이 확인할 것

노션에서는 선택 과제지만, 이 팀은 네 가지 모두 구현하기로 정했다. 아래는 각 보너스의 **평가·연동 검사**이며, 실제 모델·자동화 기능을 만든 것으로 간주하지 않는다.

| 기능 | 받아야 할 기록 | 평가 항목 |
|---|---|---|
| 이상거래 탐지 | 자산·시각·점수·임계값·버전·비중 변경 | 인위적 급등락 테스트에서 알림/축소 연동, 과거 실험의 비용·MDD 변화. 정답 라벨 없으면 정확도/F1을 주장하지 않음 |
| 차트 Vision | 이미지 생성 기준일·분류 결과·신뢰도·모델 버전·에이전트 도구 호출 ID | 미래 봉 미포함, LangGraph 에이전트 도구 호출 확인, 정답셋이 있을 때 macro-F1·클래스별 재현율·혼동행렬. 합성/실제 차트 성적 분리 |
| 공정성 | 날짜별 ETF 보유종목·섹터/규모 분류·분류 버전 | ETF 비중과 실제 기초자산 노출 구분, 섹터·대형/중소형 비중 및 수익 분포, 완화 전후 집중도·수익·MDD |
| MLOps | MLflow run/model ID·데이터/코드 버전·수집/재학습 일별 실행 기록 | 같은 산출물 재조회 가능, 일일 수집·재학습 예약과 실패 기록 확인, 모델 교체 이력 확인, 재학습 모델을 과거 테스트의 과거 시점에 끼워 넣지 않음 |

ETF 자체의 순자산 규모를 ETF가 보유한 주식의 시가총액 규모로 해석하지 않는다. 과거 편입내역이 없으면 공정성 분석 가능 범위를 제한한다. 편향이 발견되면 완화 전후 결과까지 확인한다. 위 수치의 성능 합격선을 근거 없이 만들지는 않으며, 정답 데이터가 없는 기능은 연결 검증과 한계를 먼저 보고한다.

## 9. 팀 공유용 데이터·모델 계약

**목표 전달 규격**이다. 아래 파일들이 현재 데모에서 모두 생성되는 것은 아니다. 현재 데모는 `evaluation.json`, 실행별 `ledger.parquet`·`weights.parquet`·`decisions.json`, 그림 파일을 사용한다. wide 가격표와 현재 모델 필드는 [팀 전달 자료](team_handoff.md)를 따른다. 이 규격으로 전환할 때 변환 어댑터·스키마 버전을 함께 구현해야 한다.

표 파일은 Parquet, 설정·스키마는 JSON, 실행 목록은 JSONL을 사용한다. 시각은 UTC timezone-aware, 거래일은 미국 현지 YYYY-MM-DD. 금액·평가값 float64, 수익률·비중은 소수(1%=0.01). 모델 입력 dtype은 원본 유지.

| 파일/자료 | 핵심 필드 | 사용 목적 |
|---|---|---|
| market_daily.parquet | date, asset_id, adj_close, raw OHLCV, log_return_1d, available_at, is_imputed, is_tradable | 시장 입력·누수·품질 검사 |
| reference_daily.parquet | date, return_start_at/end_at, benchmark_id, benchmark_return_simple, rf_daily_simple | 상대성과·위험조정 지표 |
| runs.jsonl | run_id, fold_id, strategy, reward_type/params, seed, model_id, status, 버전들 | 결과가 어떤 실험에서 나왔는지 추적 |
| portfolio_daily.parquet | run_id, date, equity_start/end, net_return_simple/log, traded_notional, commission, slippage, drawdown, termination_reason | 12개 지표와 전체 기간 기록 |
| decisions.parquet | run_id, decision_id, observation_id, decision_at, execution_at, model_id | 설명할 실제 결정 식별 |
| observations + feature_schema | 실제 raw/model 입력값, feature_name, index, lag, shape, dtype, input_space, available_at | 모델 입력 재현·SHAP |
| weights.parquet | run_id, decision_id, asset_id, weight_before, weight_policy, weight_executed | 행동 변환·안전 규칙 분리 |
| risk_tags / risk_actions | tag_id, decision_id, rule_id/version, 출처·시각, before/after, reason | 위험 정보에서 비중 변경까지 추적 |
| model_manifest.json | checkpoint, hash, dependencies, preprocessing, asset_order, action_to_weights, feature_schema_version | 모델을 같은 방식으로 로드 |

모든 실행에 `dataset_version`, `feature_schema_version`, `evaluation_spec_version=1.0`, `code_version`, `execution_model_id`, `risk_mode`, `risk_rule_version`을 기록한다. 관계가 있는 자료는 `run_id`·`decision_id`·`model_id`로 연결한다.

### Evaluation이 생성하는 파일

- `metrics.json`: run/fold/seed, 12개 지표, 단위·계산 불가 이유, 목표 판정.
- `curves.parquet`: run/date, 계좌 가치·누적수익률·drawdown·벤치마크.
- `stat_samples.parquet`: month/fold/strategy/reward/seed 또는 seed 집계 표시, 월 수익률, 국면.
- `anova.json`, `tukey.json`, `bootstrap.json`: 분석 규칙·표본 수·결과·한계·상태.
- `shap_groups.json`: group_id와 구성 feature_name/index 목록. 모든 입력 피처를 중복 없이 포함한다.
- `shap_contributions.parquet`: explanation_id/decision_id/target_asset/group_id, group_shap_value. 이전 개별 feature별 기여도 테이블과 혼용하지 않는다.
- `shap_explanations.json`: 기준값·정책/최종 비중·설명 버전·배경 행 ID·가산 오차·안정성 상태. API에서 기여도 테이블과 함께 조회한다.
- `quality_report.json`, `figures/`: 데이터·원장·설명 검증 결과와 Summary/Force·성과 그래프.

파일명은 실행별 디렉터리 아래에 사용한다. 서로 다른 실행의 같은 이름 파일을 덮어쓰지 않는다.

### 파트별 최초 전달 요청

- **Data Pipeline**: 10개 자산의 공통 거래일·수정가격, 벤치마크/RF, 피처 스키마, 원본/정규화 구분, 품질 보고서. 우선 실제 5거래일 샘플로 날짜·단위를 맞춘다.
- **RL**: Gymnasium 환경에서 학습한 PPO 모델 1개, 전처리 상태, 행동→비중 변환 코드, 같은 입력에 대한 정답 비중 샘플 5개, 계좌/결정/비중 기록 5거래일, 모델별 Episode Reward 학습 로그. 작은 임시 모델로 연동해도 되지만 최종 모델과 구분한다.
- **RAG**: 출처·시각이 있는 태그 3개(활성/만료/관련 없음)와 결정 연결 예제, 데이터 커버리지 보고. 위험 유형·상태 스키마도 함께 전달한다.
- **프론트엔드/API**: 아래 응답 구조로 임시 JSON부터 연결한다. 새 모델 학습이나 SHAP 계산이 끝날 때까지 화면 개발을 기다리지 않는다.

Evaluation은 비교 전략·평가 실행 순서·지표·통계·설명 함수를 구현하는 범위로 잡는다. 공통 계좌 원장·모델 내부는 RL 코드와 연결한다. FastAPI 서버 전체·MLflow 운영·보너스 모델을 자동으로 Evaluation 담당 업무로 넘기는 것은 아니다.

## 10. API·대시보드 전달과 속도 기준

**최종 서비스 목표**다. 현재 평가 API는 사전 계산 조회만 제공하며 모든 필터·상태·새 결정 설명 경로가 구현된 것은 아니다. 기존 API의 409/404/503 동작과 목표 상태 매핑은 [구현 상태](implementation_status.md)에 구분했다.

- `GET /backtest`: experiment/run/fold/strategy/seed 필터 → 12개 지표, 계좌/수익/MDD 곡선, benchmark ID, ANOVA·Tukey·보완 분석, 목표 달성 상태.
- `POST /explain`: 유효한 run_id + decision_id + target_asset → 정책 비중·최종 비중·기준값·기여도·안전 규칙·설명 상태. 현재 추천도 `decision_id`로 추적한다.
- 모든 응답: spec_version, 계산 기간, 단위, 생성 시각, 관련 버전, status/reason.
- 계산 불가 값은 JSON `null`이다. NaN/Infinity를 반환하지 않으며 프론트엔드는 ‘계산 불가/자료 부족’과 이유를 표시한다.
- 상태는 `ok`, `valid_with_warning`, `incomplete`, `data_invalid`, `insufficient_sample`, `not_available`, `failed`를 구분한다. 세부 경고는 warnings 배열에 담는다.
- Streamlit은 API 결과만 사용한다. 모델 파일이나 분석 파일을 직접 로드하지 않는다.
- 백테스트와 SHAP은 사전 계산을 우선한다. **사용자에게 조회 가능하다고 표시하는 모든 결정**의 SHAP 결과를 준비한다. 유효한 결정이지만 결과가 없는 경우는 `incomplete`로 표시해 기능 미완료로 집계하고, 모르는 `decision_id`만 `not_available`로 반환한다. 대표 날짜만 미리 계산한 결과로 모든 결정을 설명할 수 있다고 주장하지 않는다.
- 현재 시장 데이터로 새 결정을 내리는 `/optimize` 경로는 최종 추천마다 정책 비중·안전 규칙 기록·출처 연결을 남기고 `/explain`에서 같은 결정 ID를 설명할 수 있어야 한다. 새 결정의 SHAP 계산을 요청 시 수행한다면 완료까지의 시간을 별도로 측정한다.
- **속도 시험**: 같은 기기에서 endpoint별 실제 성공 요청 100회, 동시 요청 1개로 측정. p50/p95/max, 콜드 첫 요청, 캐시 여부, 응답 크기를 기록한다. 측정된 각 성공 요청이 5초 이내인지 확인하고, 한 건이라도 초과하면 해당 시험의 5초 목표는 미달이다.
- `/backtest`·`/explain`의 캐시 조회 통과는 **캐시 조회 성능**이다. 캐시 없는 새 설명의 전체 계산 시간도 따로 보고한다. 작업 접수만 5초 이내였다고 새 추론 완료 조건을 충족했다고 주장하지 않는다.
- 5초 조건을 캐시 전용으로 바꾸지 않는다. 실제로 새 결정을 설명하는 요청이 5초를 넘으면 해당 경로의 성능 기준은 **미달**로 기록하고 계산 방식을 최적화해야 한다.

## 11. 개발 완료·품질 검사 기준

필수 오류는 즉시 중단하고 결과에 기록한다. 일부 전략만 조용히 제외해 좋은 비교표를 만들지 않는다.

| 검사 | 완료 기준 |
|---|---|
| 기본키·버전 | 중복 0건, FK·파일 해시·스키마 일치 |
| 시간 순서 | 미래 피처·미래 뉴스 사용 0건 |
| 정규화 | 학습 구간 외 fit 0건, 평가 중 통계 변경 0건 |
| 수익률 대조 | 원장 비율과 net_return_simple 차이 ≤1e-8 |
| 원장 잔액 | 계좌 = ETF 평가액+현금, 상대 오차 ≤1e-8, 숨은 입출금 없음 |
| 비중 | 현금 포함 합계 오차 ≤1e-6, 음수·차입 없음, 목표 비중 상한 검사 |
| 비용 | 매수·매도 모두 적용, 이중 차감 0건 |
| MDD 종료 | 15% 초과 시 종료 기록, 청산 비용·남은 기간 기록 존재 |
| SHAP | 실제 함수 일치 ≤1e-6, 가산 오차 ≤1e-3, 불안정성 경고 보존 |
| 통계 | 3검정 모두 실행하고 F/p/η²/해당 Tukey·보완 결과 저장. 불가 사유가 있으면 과제의 통계 요구는 `incomplete` |
| 재현성 | 동일 모델·데이터·설정의 CPU 재실행에서 수익률·비중 차이 ≤1e-6, 환경 차이 공개 |
| 산출물 | 구간·seed 원본, 12지표, 설명 그림, 통계표, 실패 사례, 면책 문구 |

Evaluation 결과는 팀의 전체 제출물에도 들어가야 한다. 과제 원문에는 6개 대시보드 화면, FastAPI의 5개 엔드포인트와 Pydantic/Swagger, Docker Compose, README, 20페이지 이상 PDF 보고서가 별도로 요구된다. 평가 담당은 12개 지표·3가지 ANOVA·SHAP Summary/Force Plot·실험 선택 근거·실패 분석을 API/프론트엔드/보고서 담당에게 전달하고 화면·보고서에 실제 반영됐는지 확인한다. 이 절의 평가 파일만 만들었다고 전체 과제 요구가 완료된 것은 아니다.

pytest는 이 파트만 우선 15개 이상을 목표로 한다. 과제 전체 최소 10개와 별개인 개발 목표다.

1. 100→110의 수익률 10%.
2. +10% 후 −10%의 누적 수익률 −1%.
3. 100→120→90의 MDD 25%.
4. 로그/단순수익률 왕복 변환.
5. 비용 20,000×0.00065=13.
6. 분모 0 지표의 null 처리.
7. 벤치마크/RF 날짜 불일치 거부.
8. 미래 피처·뉴스 거부.
9. 정규화 fit 구간 검사.
10. MDD 정확히 15%와 초과의 경계.
11. 종료 후 청산·현금 유지.
12. MVO 제약·실패 대체 기록.
13. SHAP 함수 출력 일치·가산성.
14. 같은 MVO를 seed별 복제하지 않는 통계 표본 생성.
15. JSON NaN/Infinity 금지 및 계산 불가 이유 전달.

## 12. 구현 순서와 도구

1. **데이터 계약 검사**: pandas, NumPy, PyArrow, Pydantic. 먼저 5일 샘플의 단위·시간·키를 확인한다.
2. **12개 지표와 테스트**: pandas, NumPy, statsmodels OLS, pytest. PPO 없이 손계산 예제로 시작한다.
3. **기준 전략·원장 연결**: SciPy SLSQP와 공통 거래 엔진. 동일가중부터 구현한다.
4. **Walk-Forward 실행**: 구간·seed·보상 반복을 관리하고 RL 학습 함수를 호출한다. 기준·모델 버전을 먼저 고정한다.
5. **통계 분석**: statsmodels, SciPy, arch. 월 표본·국면·가정 점검·보완 구간을 자동 생성한다.
6. **SHAP 한 건→정기 배치**: shap, RL과 동일한 PyTorch/SB3, 고정 Grouped masker. 실제 함수 출력 대조부터 통과시킨다.
7. **전달·보고서**: JSON/Parquet, Matplotlib, HTML Force Plot, 팀 FastAPI, MLflow 실험 ID 연결.

Python·PyTorch·SB3·Gymnasium·SHAP 등은 RL과 호환되는 환경으로 맞추고 작은 모델 로드 시험 후 정확한 버전을 lockfile에 고정한다. 이 기준 원안을 작성한 것은 학습·성능 측정 완료를 의미하지 않는다. 현재 코드와 합성 데이터 검증 범위는 [구현 상태](implementation_status.md), 이전 검증 기록은 [개발 로드맵](roadmap.md)을 확인한다. 이번 저장소 문서화에서는 평가 코드를 변경하지 않았다.

## 13. 변경 관리

- 변경 시 버전, 변경 이유, 영향을 받는 기존 실행, 변경 전에 이미 본 테스트 결과를 기록한다.
- 자산·거래 시점·보상·목표 집계·통계 표본을 바꾸면 기존 결과와 같은 실험으로 합치지 않는다.
- 자료 부족은 누락 상태로 남긴다. 데이터 확보가 안 된 실험을 성공한 것으로 처리하지 않는다.
- 처음에는 이 기준으로 개발을 진행하되, 통계 설계 검토 의견이나 실제 호환성 문제가 있으면 변경 근거를 남겨 개선한다. 평가 결과를 유리하게 만드는 사후 변경과 구분한다.

교육용 프로젝트의 연구·평가 기준이다. 실제 투자 조언이 아니며, 백테스트 성과는 미래 수익을 보장하지 않는다.
